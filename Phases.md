# Phases.md — Build Order

> Rule: one phase per AI session where possible. Do not start phase N+1 until phase N meets its acceptance criteria and Memory.md is updated.

## Phase 0 — Project Skeleton (½ day)
**Build:** Repo init, folder structure from Architecture.md, `requirements.txt`, `.gitignore`, `configs/labels.json`, `configs/training.yaml` with initial values, empty `__init__.py` files, pytest wired up with one trivial passing test.
**Acceptance:** `pip install -r requirements.txt` succeeds in a fresh venv; `pytest` runs green; folder tree matches Architecture.md.

## Phase 1 — Data Pipeline (2–3 days)
**Build:** `src/data/download.py` (Kaggle API → `data/raw/`), `src/data/preprocess.py` (clean text minimally — the model should see realistic noisy text; dedupe; merge Jigsaw 2018 + Civil Comments with unified label schema; stratified 80/10/10 split by the rarest label; save parquet), `src/data/dataset.py`, `tests/test_preprocess.py`.
**Key decisions:** binarize Civil Comments continuous toxicity scores at ≥0.5 (document this); cap dataset at a size trainable in <3 Colab GPU-hours (~250–300K rows) via stratified sampling.
**Acceptance:** `python -m src.data.preprocess` produces 3 parquet files; a printed summary shows row counts and per-label positive rates; no text overlap between splits (test asserts this); EDA notebook shows label distribution.

## Phase 2 — Baseline (1 day)
**Build:** `src/models/baseline.py` — TF-IDF (word 1-2 grams + char 3-5 grams) + One-vs-Rest Logistic Regression with class weights. Evaluate with the shared `src/evaluation/evaluate.py` (build the model-agnostic evaluator NOW, in this phase).
**Acceptance:** `metrics/baseline.json` exists with per-label precision/recall/F1, micro/macro F1, PR-AUC. Evaluator accepts any `predict_proba`-style function.

## Phase 3 — Fine-Tune DistilBERT (3–4 days, GPU)
**Build:** `src/models/train.py` — `distilbert-base-uncased`, multi-label head, `BCEWithLogitsLoss` with `pos_weight` from training-set label frequencies, max_length=128, lr=3e-5, 2–3 epochs, fp16, checkpoint per epoch, early stopping on val macro-F1. Runs on Colab; checkpoints to Drive.
**Acceptance:** `models/distilbert-finetuned/` contains final model + tokenizer; `metrics/distilbert.json` generated by the SAME evaluator as Phase 2; macro-F1 beats baseline (if not, stop and investigate before proceeding).

## Phase 4 — Evaluation & Threshold Selection (2 days)
**Build:** `src/evaluation/thresholds.py` — per-label PR curves (saved to `metrics/pr_curves/`), select per-label thresholds targeting max recall subject to precision ≥ 0.90, write `configs/thresholds.json`. Also select the flag-band lower threshold (e.g., the 0.5-precision point) for the allow/flag/block decision logic. Error analysis: dump 50 worst false positives + false negatives to `metrics/error_analysis.md`.
**Acceptance:** thresholds.json exists with documented precision/recall at each threshold; PR curve PNGs exist; error analysis file exists. **This is where the resume-bullet numbers come from — record them exactly.**

## Phase 5 — ONNX Export, Quantization & Benchmark (2–3 days)
**Build:** `src/models/export_onnx.py` (Optimum export → dynamic INT8 quantization → `models/onnx/`); re-run the shared evaluator on the ONNX model → `metrics/onnx_quantized.json` (verify F1 drop < 1% vs PyTorch, else fall back per Rules.md); `src/evaluation/benchmark.py` — CPU, batch=1, seq_len=128, 50 warmup + 1000 timed runs, log p50/p95/p99 + hardware info for PyTorch vs ONNX vs ONNX-INT8 → `metrics/latency_benchmark.json`.
**Acceptance:** all three latency configs benchmarked; ONNX-INT8 p95 < 50ms on documented hardware; accuracy delta documented.

## Phase 6 — Serving API (2 days)
**Build:** `src/serving/` — FastAPI app with lifespan-loaded ONNX session, `POST /moderate` (per-label scores + allow/flag/block decision + measured latency_ms), `GET /health`, Pydantic schemas, `tests/test_api.py` with TestClient covering: clean text → allow, known-toxic text → block/flag, empty text → 422, >5000 chars → 422.
**Acceptance:** `uvicorn src.serving.app:app` serves; all API tests green; manual curl of the endpoint returns a well-formed response with latency under budget.

## Phase 7 — Demo, README & Polish (2 days)
**Build:** `demo/streamlit_app.py` (text box → live scores as bars, decision badge, latency readout; a few preset example buttons); README with project summary, architecture diagram, the results comparison table (baseline vs PyTorch vs ONNX vs ONNX-INT8: macro-F1, precision@recall, p95 latency), quickstart, and limitations section (English-only, obfuscation vulnerability, dataset bias).
**Acceptance:** demo runs with `streamlit run demo/streamlit_app.py`; every number in README traces to a `metrics/` file; repo clones and runs from scratch following README alone.

## Phase 8 (Optional) — Stand-Out Extras
Docker + docker-compose; token-level attribution highlighting in the demo; obfuscation robustness mini-study; locust load test. Only after Phase 7 is fully done.
