# ModGuard — Real-Time Toxic Content Moderation API

A production-style ML service that classifies social media text for toxicity
(6 labels, multi-label) using a fine-tuned DistilBERT model, optimized with
ONNX Runtime and served through a FastAPI endpoint. Built end-to-end: data →
training → rigorous evaluation → inference optimization → serving → demo.

## How it works

**Training-time (offline, mostly on Colab GPU — see `notebooks/02_train_colab.ipynb`):**

```
Jigsaw Toxic Comment + Civil Comments (Kaggle)
        │
        ▼
data pipeline: clean, dedupe, merge, stratified split
        │
        ├──► TF-IDF + LogisticRegression baseline ──► metrics/baseline.json
        │
        ▼
DistilBERT fine-tuning (multi-label, pos_weight-ed BCE loss)
        │
        ▼
PR-curve threshold selection ──► configs/thresholds.json, metrics/error_analysis.md
        │
        ▼
ONNX export (Optimum) → INT8 dynamic quantization ──► metrics/onnx_quantized.json
        │
        ▼
Latency benchmark (PyTorch vs ONNX-FP32 vs ONNX-INT8) ──► metrics/latency_benchmark.json
```

**Inference-time (online, the `POST /moderate` path):**

```
Client ──POST /moderate {"text": "..."}──► FastAPI
                                             │
                                             ▼
                              ONNX Runtime session (loaded once at startup)
                                             │
                                             ▼
                              Sigmoid → per-label scores
                                             │
                                             ▼
                    Per-label threshold logic (configs/thresholds.json)
                                             │
                                             ▼
              {"scores": {...}, "decision": "allow|flag|block", "latency_ms": 24.8}
```

Decision logic is per-label (each of the 6 labels has its own PR-curve-derived
`block_threshold` / `flag_threshold`, since base rates and score distributions
differ a lot between e.g. `toxic` and `severe_toxic`); the overall decision is
whichever label triggers the most severe outcome.

## Results

All numbers below are generated by scripts in this repo and read directly
from `metrics/*.json` — see [Rules.md](Rules.md)'s metrics-integrity rules.
Test set: 30,000 held-out examples (10% stratified split), identical across
every row.

| Metric | Baseline (TF-IDF+LR) | PyTorch DistilBERT | ONNX Runtime INT8 |
|---|---|---|---|
| Macro F1 | 0.4449 | 0.5513 | 0.5547 |
| Macro PR-AUC | 0.4775 | 0.5857 | 0.5873 |
| Micro F1 | 0.5564 | 0.6392 | 0.6477 |
| p95 latency (bs=1, seq_len=128) | — | 192.3ms | 162.4ms |

Latency was benchmarked on Colab's free-tier CPU (`Intel(R) Xeon(R) CPU @
2.00GHz`, 2 vCPUs — see `metrics/latency_benchmark.json` for the full
methodology: 50 warmup + 1000 timed runs). **This misses the project's <50ms
p95 target by ~3x.** Quantization gave a real ~15% p95 reduction over
PyTorch, but the target requires stronger CPU hardware than Colab's shared
free tier provides — a single live request against the same INT8 model on a
local Apple M3 measured **24.77ms** (well under target), which is real
evidence the miss is a hardware artifact and not a modeling problem, though
it's one request, not the same rigorous warmup/1000-run methodology, so the
two numbers shouldn't be treated as directly comparable.

**Precision @ recall, block tier (target ≥90% precision, from
`configs/thresholds.json`):**

| Label | Block precision | Block recall | Flag recall (≥50% precision) |
|---|---|---|---|
| toxic | 90.1% | 36.9% | 82.4% |
| obscene | 90.2% | 43.0% | 84.9% |
| insult | 90.1% | 37.9% | 83.8% |
| severe_toxic | 100.0%* | 8.0% | 80.0% |
| identity_hate | 100.0%* | 0.4% | 44.4% |
| threat | 100.0%* | 6.5% | 21.0% |

\* Reported as 100% because very few examples score above that label's
extreme threshold (0.999+) in the test set — not a robust estimate. The PRD
target was ≥90% precision **at ≥80% recall**; that combination was only hit
at the looser "flag" tier, not "block." The three rarest labels
(`severe_toxic`, `threat`, `identity_hate`) can reach high block-tier
precision only by sacrificing almost all recall — see
`metrics/error_analysis.md` and [Limitations](#limitations) below.

## Quickstart

The repo doesn't commit raw data, trained model weights, or ONNX exports
(`data/` and `models/` are git-ignored — see `.gitignore`); those are
regenerated by the pipeline below, following [Phases.md](Phases.md)'s build
order. `metrics/*.json` and `configs/thresholds.json` (the actual results)
**are** committed, so you can read the real numbers above without rerunning
anything.

**1. Local dev environment (data pipeline, baseline, tests):**
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest
```

**2. Data + baseline** (needs a Kaggle API key at `~/.kaggle/kaggle.json`):
```bash
python -m src.data.download
python -m src.data.preprocess
python -m src.models.baseline
```

**3. Fine-tuning, thresholds, ONNX export/quantization/benchmark** — these
need a GPU (fine-tuning) and are run on Google Colab; open
[`notebooks/02_train_colab.ipynb`](notebooks/02_train_colab.ipynb) via
**Colab → File → Open notebook → GitHub** and run it end to end. It uploads
your `data/processed/*.parquet`, trains, evaluates, exports, and copies every
result back to Google Drive for you to download.

**4. Serve the API** (once `models/onnx/int8/` exists locally, from step 3):
```bash
uvicorn src.serving.app:app --reload
curl -X POST http://localhost:8000/moderate -H "Content-Type: application/json" \
  -d '{"text": "Have a great day!"}'
```

**5. Run the demo:**
```bash
streamlit run demo/streamlit_app.py
```

## Limitations

- **English-only.** The underlying data (Jigsaw Toxic Comment Challenge,
  Civil Comments) is English-only; the tokenizer and model have no
  multilingual capability.
- **Obfuscation vulnerability.** No adversarial/obfuscation robustness
  training was done (e.g. leetspeak substitutions, spacing tricks). The
  model was trained on natural text as it appears in the source datasets.
- **Rare-label recall collapse at the block tier.** `severe_toxic`,
  `threat`, and `identity_hate` have too few positive test examples for a
  stable 90%-precision estimate; their block-tier recall is effectively
  unusable (0.4%–8%) in this configuration. In a real deployment, these
  labels would need either more labeled data or a different operating point
  (e.g. flag-only, never auto-block) than the common labels.
- **Dataset label noise.** Manual review of `metrics/error_analysis.md`'s
  worst false positives surfaced cases that look like correct toxicity
  calls the model got right but the source dataset's ground truth may have
  mislabeled (e.g. explicit profanity marked non-obscene) — some of the
  reported "false positive" rate is likely dataset noise, not model error.
- **Latency is hardware-dependent.** The rigorously-benchmarked p95 number
  (162.4ms) was measured on Colab's weak shared CPU and misses the <50ms
  target; see [Results](#results) above for the informal same-model
  same-day evidence (24.77ms on a local Apple M3) that stronger hardware
  would likely close that gap, and Decision #12/#13 in
  [Memory.md](Memory.md) for the full reasoning trail.
- **Portfolio scope, not a production system.** No auth, rate limiting,
  human-review queue, or monitoring/alerting exists around the `/moderate`
  endpoint — those are explicitly out of scope (see [PRD.md](PRD.md)).
