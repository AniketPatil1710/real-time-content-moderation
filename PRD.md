# PRD.md — Real-Time Content Moderation System

## 1. Overview

**Project name:** ModGuard — Real-Time Toxic Content Moderation API

**One-liner:** A production-style ML service that classifies social media text as toxic or policy-violating in under 50ms, using a fine-tuned DistilBERT model optimized with ONNX Runtime.

**Why this exists:** Platforms like Meta, Reddit, and YouTube moderate billions of posts using ML classifiers as the first line of defense before human review. This project replicates that pattern end-to-end at portfolio scale: data → training → rigorous evaluation → inference optimization → serving → demo.

**Primary purpose:** Resume/portfolio project demonstrating applied NLP, MLOps, and inference optimization skills for ML engineer roles.

## 2. Target Users

1. **Hypothetical platform integrator (design persona):** A backend engineer at a social platform who needs a drop-in `POST /moderate` API that returns a decision (allow / flag / block) fast enough to sit in the posting path.
2. **Recruiter / interviewer (real audience):** Someone reviewing the GitHub repo who should understand the project in 60 seconds from the README and be able to verify claims (metrics table, benchmark scripts, demo).
3. **The developer (Aniket):** Must be able to defend every number in interviews — every metric must be reproducible via a script in the repo.

## 3. Goals & Success Metrics

| Goal | Metric | Target |
|------|--------|--------|
| Classification quality | Precision at stated recall (report BOTH) | ≥ 90% precision at ≥ 80% recall on held-out test set |
| Ranking quality | PR-AUC | Report actual value (no target — must beat TF-IDF baseline) |
| Inference speed | p95 latency, batch=1, seq_len=128, CPU | < 50ms (measure p50 and p95) |
| Optimization impact | Speedup: PyTorch vs ONNX vs ONNX-INT8 | Report actual speedup with accuracy delta |
| Reproducibility | Every reported number regenerable from a script | 100% |

**Anti-goal on metrics:** Never report precision alone without recall. Never report average latency without p95. Never report latency without hardware specs.

## 4. Core Features (Must Have — MVP)

1. **Data pipeline:** Download, clean, and merge Jigsaw Toxic Comment + Civil Comments datasets into a unified ≥200K-example multi-label dataset with train/val/test splits (stratified, no leakage).
2. **Baseline model:** TF-IDF + Logistic Regression, evaluated with the same metrics as the transformer.
3. **Fine-tuned DistilBERT:** Multi-label classification (toxic, severe_toxic, obscene, threat, insult, identity_hate) with class-imbalance handling.
4. **Evaluation module:** PR curves per label, threshold selection utility, metrics report (JSON + markdown table) generated by script.
5. **ONNX optimization:** Export via HuggingFace Optimum, dynamic INT8 quantization, side-by-side accuracy verification.
6. **Latency benchmark:** Scripted benchmark (warmup runs, 1000 timed runs, p50/p95/p99, hardware info logged).
7. **Serving API:** FastAPI `POST /moderate` endpoint returning per-label scores + decision (allow / flag / block) based on configurable thresholds. Model loaded once at startup.
8. **Demo UI:** Streamlit app — type a comment, see live scores, decision, and latency.
9. **README:** Results table (baseline vs PyTorch vs ONNX vs ONNX-INT8: F1 / precision@recall / p95 latency), architecture diagram, quickstart.

## 5. Nice to Have (Post-MVP, only if time permits)

- Token-level highlighting of toxic spans (attention or SHAP).
- Dockerfile + docker-compose for one-command startup.
- Simple obfuscation-robustness test set (l33tspeak, spaced-out slurs) reported as a limitation study.
- Load test with `locust` (requests/sec at p95 < 50ms).

## 6. Explicit Non-Goals

- No multilingual support (English only).
- No image/video moderation.
- No training from scratch — fine-tuning only.
- No Kubernetes / cloud deployment (Docker is the ceiling).
- No user auth on the API.
- No real user data — public datasets only.

## 7. Constraints

- **Compute:** Free Colab/Kaggle GPU for training; local CPU for inference benchmarks.
- **Budget:** ₹0. All tools open source.
- **Timeline:** 2–3 weeks part-time (see Phases.md).
- **Dataset licenses:** Jigsaw datasets are CC0/public — safe to use and cite.

## 8. Key Risks

| Risk | Mitigation |
|------|-----------|
| Quantization degrades precision | Verify accuracy pre/post quantization; fall back to FP16 or non-quantized ONNX if drop > 1% F1 |
| Class imbalance tanks minority-label recall | Weighted BCE loss; report per-label metrics, not just micro-average |
| Latency target missed on weak hardware | Report actual hardware; seq_len 128 cap; quantization; this is why we measure p95 not average |
| Colab session limits interrupt training | Checkpoint every epoch to Google Drive; keep total training under 3 GPU-hours |
